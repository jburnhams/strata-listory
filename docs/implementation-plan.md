# Implementation plan

- [x] **M0 scaffold**: repository layout, `.venv` setup scripts (`scripts/setup_env.sh`, `scripts/setup_env.ps1`), `./app` and `app.cmd` launchers, `oslib.py`, `settings.py`, `doctor` CLI command.
- [x] **M1 hello-world backend & CLI**: `greet.py` domain module, `hello` and `messages` CLI commands, FastAPI server (`server/app.py`) with `landing.html` fallback.
- [x] **M2 React web app**: Vite + React 19 + Tailwind CSS v4 frontend (`web/`), hash router (`route.ts`), reverse-proxy-safe API client (`api.ts`), greeting and settings pages.
- [x] **M3 test suites & CI**: hermetic pytest unit and integration suites, Vitest unit (node) and integration (jsdom + msw) suites, coverage gates, and GitHub Actions workflows (`unit.yml`, `integration.yml`).
- [x] **M4 catalogue**: `catalogue.py` book model and SQLite store, `add`/`list`/`show`/`edit`/`remove` CLI, `/api/books` endpoints, web library page (add, search, status filter, remove), `library_dir` setting. Replaced the template's hello-world greeting module.
- [x] **M5 folder scan (names only)**: `scan.py` finds books and radio under `library_dir` and parses names; `./app scan`, `/api/scan`, library page button.
- [ ] **M5b file metadata**: read embedded tags, durations and chapters (ffprobe or mutagen) to improve titles and fill `duration_seconds`.
- [x] **M6 processing**: `./app process` into a separate final library (mono mp3 chapters, per-chapter VBR tier, loudness to -18 LUFS, lossless copy of small mono mp3s); ffmpeg/LAME/mp3gain.
- [ ] **M6b process the library**: run it over confirmed books, review the plan totals first; later: also unconfirmed books once matching has been reviewed; then switch the app's library to the final folder and drop the inbox copy.
- [x] **M7 storage**: SQLite (`db.py`) with automatic verified backups and restore (`backup.py`).
- [x] **M8 matching, first source**: AudiobookDB title/ASIN lookup with scored suggestions and a review UI (confirm / ignore).
- [x] **M8b modular providers**: Audnexus, Audible catalogue search and AudiobookDB behind one interface; ordered or combined queries; `match-test` to compare.
- [ ] **M8c improve the hit rate**: sample on 2026-10-30 gave ~37% good / ~55% any with all three providers; the rest are mostly names the scanner could not clean (chapter files, radio-like folders). Next: better title cleaning and author detection, tag-based titles, Open Library for non-Audible titles.
- [x] **M9 community data**: Hardcover as a provider and as the source of ratings, review counts, genres/moods/warnings and top reviews for confirmed books (`enrich.py`, book page, mirror).

- [ ] **M10 evidence and identity**: `./app evidence-report [IDS] --limit 20 --stride 25` emits a read-only JSON snapshot of stored provider metadata, all local Audible sidecars and full ffprobe results for every discovered audio file. Separates work and recording identity, preserves field alternatives and manual locks, checks duration and album tags, and treats Audible/Audnexus as one family. Automatic processing remains disabled. Next: fresh multi-provider collection with append-only response history, explicit recording/abridgement fields throughout providers, candidate association and benchmark-labelled samples before enabling approvals. Existing response caches expire and are not an evidence archive; the report preserves only what is still available. Save each report as a new dated JSON artifact.

- [x] **M10a fresh Open Library**: opt-in `evidence-report --fresh-openlibrary` fetches and archives search, unique work details and ratings without catalogue changes; carries work description, subjects, original year and source-specific ratings into the report. Other providers still use stored evidence.

- [x] **M10b source-alignment pilot**: offline `python -m app.audio_compare`, with source hashes, energy-window fingerprints, conservative matching, coverage and sampled diagnostics. Hitch-22 full/parts comparison and full quality review completed; originals retained. Next: calibrate on more speech/performances, stronger fingerprints, sample-accurate boundary checks, semantic chapter metadata, channel/noise diagnostics and integration into book grouping/approval plans.

- [x] **M11 staged ingest**: durable run/stage metrics and policy revisions, tag-aware groups and source manifests, raw multi-provider archives, work/recording metadata, per-file fingerprint alignment, full quality measurements with content-hash reuse, explicit source selection and processing plans. CLI/API/Ingest page expose retries, evidence, metrics and threshold replay. Automatic approval/execution remain off by default; enabled jobs are group-scoped and integrity checked. Final output retains metadata provenance and raw provider evidence. See [ingest-pipeline.md](ingest-pipeline.md).
